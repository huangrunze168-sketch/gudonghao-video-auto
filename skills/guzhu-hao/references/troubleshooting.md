# 常见问题

## 先看这三类

### 1. 成片比预期短，片头整段不见了

**原因**：`.jypack` 里部分素材保持**打包加密**状态（实测是图片），剪映导入才会解密重绑。
直接解包渲染时，引擎读不到素材就会**静默丢弃整个片段**——片头画面段一消失，成片就少一整段。

**处理**：
- 脚本会自动把不可读的图片替换成纯色图（颜色由 `media.solid_color` 控制，默认黑），
  并在 `report.json` 的 `repaired_media` 里逐条记录。
- **其它类型素材不可读时脚本直接失败**，不会交出残缺成片。报错形如
  `包内素材不可读且无法自动修复，已停止而不是交出残缺成片：[...]`。
- 若必须保留原图，请在剪映里导出草稿包**之前**把该图片换成自己的素材，或先用剪映导入一次该包。

### 2. 改了草稿但成片没变化

**原因**：剪映有四个必须一致的草稿镜像——根目录与 `Timelines/<时间线id>/` 下各一份
`draft_content.json` 与 `template-2.tmp`。模板包里它们常常本身就是不同步的旧内容，
只改其中之一，渲染读到的仍是旧数据。

**处理**：脚本写回时会一次性对齐全部镜像（并在测试里断言哈希相同）。若手工改过草稿，
请把四个文件重新对齐，或直接重新运行 `build`。

### 3. 歌词不出现

**原因**：模板的歌词动效卡（`text_template_lyrics`）官方资源缺 `content.json`，
引擎会静默跳过整张卡；这是资源侧的问题，不是缺文件。

**处理**：脚本已把歌词改成**可渲染的普通字幕**。若成片仍无歌词，依次检查：
`report.json` 里该首歌的 `lyric_cues` 是否 > 0；抽帧看主歌段；
确认 `lyrics` 文件的时间戳确实落在选段区间内（见下一条）。

## 报错对照表

| 报错 | 原因与处理 |
| --- | --- |
| `未找到 jianying-headless-windows 检出目录` | 用 `--project` 指定，或设 `JIANYING_HEADLESS_ROOT` |
| `时间线已加密；需要剪映引擎才能读取` | 剪映版本或 `videoeditor.dll` 指纹不匹配；必须 11.5.0.14471 |
| `文件不是受支持的 JY/ZIP 容器` / `包不是合法 ZIP` | 文件损坏或不完整；重新导出该 `.jypack` |
| `包内 CRC 校验失败` | 包传输/复制过程中损坏 |
| `模板里没有音乐轨道` / `模板里没有 TTS 引流话术` | 选的不是股东号形态的模板；对照 [模板契约](template-contract.md) |
| `无法确定模板片头与主歌的分界点` | 模板主歌段缺失或结构不同 |
| `LRC 主歌段内没有任何可用歌词` | 选段窗口与歌词时间不重合。改用 `start: "auto"`，或把 `start` 调到歌词所在区间，或去掉 `lyrics` |
| `歌曲太短：… 少于需要的 …` | 歌曲比「片头 + 主歌」还短；换歌或缩短话术 |
| `引流话术缺少有效时长` | 某句配音合成结果为空，换一个 SAPI 音色或检查自备音频 |
| `找不到音色 …` | 用 `voices` 子命令查看本机可用音色名 |
| `核心项目 draftediting_runtime.py 失败：unauthorized host process` | 剪映主进程没在运行；`official` 配音与官方链路都要求它是可信宿主 |
| `auth credential is missing: not logged in` | `official` 配音需要登录；先跑 `tools\lyra_login.py` |
| `模板里没有可沿用的官方音色` | 模板的 TTS 素材没有 `tone_speaker`；用 `intro.tts.speaker` 显式指定 |
| `官方 TTS 只能替换模板已有的 N 组配音` | 话术条数超过模板引流组数；减少话术或在剪映里把模板片头做够组数 |
| `官方没有为第 N 句产出音频` | 官方合成失败（多为权益或网络）；看 `work/draftediting-traces/` 里的完整证据 |
| `failed to read LyricStyle.json` | `lyrics.animation` 传了 `subtitle_template` 类资源；必须用 **`lyric_animation`** 类（如 `7591420714515844395`） |
| `官方识别没有产出可套动效的歌词文本段` | 主歌段没有可识别的歌声，或识别被权益/网络中断；检查 `lyrics.recognize_timeout` 与账号状态 |
| `官方工作区里找不到主歌音乐段` | 模板结构不同；确认模板主歌段是起点最晚的音乐片段 |
| 歌词在成片里不出现（但命令都成功） | 官方只写 `Timelines/<id>/`，检查脚本的镜像同步是否执行；草稿目录名必须纯 ASCII |
| `SAPI 合成失败` | 音色不可用或文本异常；换音色重试 |
| `拒绝覆盖已存在的输出` | 输出路径已存在；脚本只写新目录，改 `out` 或先清理 |
| `ffmpeg 解码失败` / `ffmpeg 裁剪失败` | 源音频损坏，或 PATH 中缺少 FFmpeg |
| `未找到 clang-cl` / `未找到 Visual Studio x64 C++ 工具链` | 安装 LLVM for Windows 与 VS 2022 Build Tools（Desktop C++） |
| `Native restoration/export did not complete` | 原生导出失败；看 `render/<歌名>/native.stderr.log` |
| `视频时长 … 与时间线 … 不一致` | 通常是加密素材导致片段被丢弃，见上面第 1 条 |
| `剪映本地草稿目录尚未初始化` | 先打开剪映创建并保存一个空白工程，再完全退出 |

## 性能与资源

- 每首歌**按次编译**原生渲染辅助程序（`clang-cl /MD`），首次约 10–30 秒，之后同一进程复用系统缓存。
- 单条渲染耗时与成片时长成正比（实测 33 秒成片在本机约 1 分钟级）。
- 默认**保留**安装到剪映草稿根下的临时草稿（`guzhu-<歌名>`），方便在剪映里核对；
  批量跑完用 `--cleanup-drafts` 让脚本自行清理，或手动删除这些目录。
- 输出的 `.jypack` 会清理孤儿素材：实测从 71 MB 降到 13 MB 左右。

## 排查顺序

1. `check` 是否全绿。
2. `report.json` 里该首歌的 `status` / `error` / `start_pick` / `repaired_media`。
3. `render/<歌名>.log` 与 `render/<歌名>/native.stderr.log`。
4. 把 `jypack/<歌名>.jypack` 拖进剪映打开播放，确认草稿本身是否正确。

草稿本身正确、只有成片不对 → 属于渲染链路问题；草稿就不对 → 属于改造逻辑问题。
