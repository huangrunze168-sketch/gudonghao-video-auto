# 模板契约

模板就是一条**已经在剪映里调好的股东号草稿**，导出为 `.jypack`。脚本用结构识别
（不依赖固定 id）来定位各个部分，因此换一条同形态的模板也能直接跑。

## 必需结构

| 部分 | 要求 |
| --- | --- |
| 音乐轨 | 至少一条音频片段，且**主歌段是起点最晚的那条音乐片段**（脚本用它作为片头/主歌分界点） |
| 引流组 | 至少一组「TTS 配音（`type: text_to_audio`）+ 字幕 + 贴纸」，三者的时间区间一一对应 |
| 主歌段 | 分界点之后有背景画面与歌词（歌词形式不限，脚本会替换） |

识别失败时会明确报错（`模板里没有音乐轨道` / `模板里没有 TTS 引流话术` / `无法确定模板片头与主歌的分界点`），
不会猜。

## 实测模板解剖（示例）

`测试.jypack`，31.567 秒，画布 2276×1280，6 条轨道：

| 区段 | 时间 | 内容 |
| --- | --- | --- |
| 片头 | 0 – 6.433s | 5 组引流：TTS（曼波讲故事）+ 5 条大字幕 + 5 个贴纸；黑底图片；音乐用歌曲 119.70–126.13s |
| 主歌 | 6.433 – 31.567s | 背景视频；歌曲 126.13–151.27s；6 张歌词动效卡 |

脚本读出的模板骨架：

```
片头分界：6.433s（5 组引流话术）
主歌段：25.133s
总时长：31.567s
```

## 脚本会改动什么

| 对象 | 改动 |
| --- | --- |
| 歌曲素材 | 换成按选段裁好的 wav；两段音乐片段的 `source_timerange` 与 `target_timerange` 重算 |
| TTS 素材与片段 | 换成新配音；文案、时长、时间轴按新话术重排 |
| 字幕素材 | 文案改写，样式区间与逐字字段同步 |
| 贴纸片段 | 跟随所属引流组重新对时（贴纸素材本身不动） |
| 主歌及其之后的所有片段 | 按片头时长差整体平移 |
| 片头画面段 | 目标/源时间区间同步缩放到新片头长度 |
| 歌词 | 模板歌词动效卡替换为可渲染的普通字幕，时间来自 LRC |
| 素材与素材库 | 清理旧歌曲、旧配音、孤儿逐词素材与随之失效的歌词动效分组 |
| 元信息 | 草稿名、`draft_id`、素材库里的音乐条目同步 |

## 不会改动什么

- 模板的版式、贴纸素材与动效、背景画面、字幕字体与描边样式。
- 源包本身（只读；所有产物写到清单里的 `out` 目录）。
- 剪映账号数据、在线资源、会员权益。

## 已知边界

- **歌词动效卡不出字**：模板卡资源在官方侧缺 `content.json`，无头渲染会被静默跳过。
  脚本改用普通字幕承载歌词；如需动效请在剪映里手工使用该模板。
- **贴纸依赖剪映本地缓存**（`Cache/effect/...`）。缓存被清理后贴纸不会出现在成片里。
- 引流话术条数不能超过模板的引流组数（需要更多组时，先在剪映里把模板的片头做够组数）。
- 原生导出只在剪映 **11.5.0.14471** 与固定 `videoeditor.dll` 指纹下启用，其它版本直接失败关闭。
