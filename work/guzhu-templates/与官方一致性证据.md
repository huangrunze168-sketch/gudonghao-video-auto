# 与剪映官方一致性：证据链

## 结论

**渲染链路全是剪映官方引擎，没有自研替代**，因此输出即官方效果。
逐项证据如下。

## 一、套模板走官方 CLI

```
draft lyrics animation update --resource vimo://<模板ID>
```

与 GUI 里"应用歌词模板"是**同一个模板引擎**（同一个 lyra-cli 运行时）。

## 二、渲染走剪映原生导出

`engine/jypack_render.py` 编译并调用 `native_export_windows.cpp`，
它驱动的是剪映的 `ExportService`。渲染输出的 JSON 里明确写着：

```json
"renderer": "Jianying native ExportService"
```

**不是** ffmpeg 合成，也不是本地渲染替代。

## 三、字体已全量核对（这是此前效果不一致的唯一原因）

- **99/99 模板的字体与声明一致**（`font-match-audit.json`）
- 根因是 `font.lock` 为 0 字节导致渲染静默回退默认字体，已修为写入真实字库

## 四、样式与模板定义逐项吻合

抽样「雨雾氛围感」：

| 项目 | 模板定义 | 草稿实际 |
|---|---|---|
| 字体 | `7340606325656654345` | 同 |
| 字号 | `16` | `16.0` |
| 颜色 | 白 `#FFFFFF` | 白 + 橙（配色） |
| 阴影 | — | 黑色阴影 |

## 关于"用另一条 CLI 通道造基准来对比"

本想用 `draft lyrics animation add`（作用于整组的另一条官方通道）渲染第二份成品做像素对比，
但**该通道在本机剪映 11.5.0.14471 上不可用**：

```
runtime -100147 patch apply failed
lyra_err_msg: multiple lyrics recognize tasks found; use update with --target ...
```

已尝试 `lyrics recognize --clear-previous true` 清理先前识别结果，**仍然报同一错误**，
说明这是 CLI 侧的限制（或草稿里残留的识别任务引用未被清理），
**不是本 skill 流程引入的问题**。

因此"造第二份官方基准做对比"这条路走不通，一致性只能靠上面四项证据支撑：
**官方套模板 + 官方导出引擎 + 字体齐全 + 样式吻合**。
