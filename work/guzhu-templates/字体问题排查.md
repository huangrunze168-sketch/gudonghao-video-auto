# 歌词模板字体问题：排查记录

## 你指出的问题（完全正确）

我出的片子字体和你用剪映做的**不一样**：
- **你截图里的雨雾氛围感**：橙色 + 白色**手写书法体**（两种颜色叠加）
- **我出的片子**：单一白色发光体（回退成了默认字体）

结论：**我用了模板的动画和排版，但字体没生效**。

## 已查明：两层原因

### 第一层：字体文件缺失（已修复）

审计全部 102 个模板的字体依赖：

| 状态 | 修复前 | 修复后 |
|---|---|---|
| 字体齐全 | 46 个 | **75 个** |
| 部分缺失 | 41 个 | 27 个 |
| 完全缺失 | 15 个 | **0 个** |

**115 个字体里 47 个不可用**，目录里只剩 `font.lock`（假下载）。

**官方 CLI 的字体下载有 bug**：

```
err_category: upstream
err_code: -100202
resource_pool err_code=-7002
download failed, code=-1008, msg=cannot unzip file
```

即服务端返回的字体包在 CLI 侧**解压失败**（包内中文文件名编码问题）。
**剪映 GUI 用另一套解压逻辑，所以你能下载、我不能。**

**绕过方式**（仍走官方接口，非本地替代）：用 `material query` 拿到官方签名 CDN 地址，
Python 直接下载 + `zipfile` 解压 + MD5 校验（`80db27b1aa13bd63e020ec62e68fc27` 与官方一致）。
结果：**41 个字体补齐**，包括雨雾氛围感缺的「默陌专辑手写体」(9.6MB)。
下载后按剪映期望的名字重命名为 `font.ttf` / `font.otf`。

### 第二层：字体引用（部分查明，未打通）

`draft text style` 有 `--font` 参数（`--seg-id` 必须**逐个段**传，逗号分隔会报
`expects raw segment ids`）。

回读草稿确认：**模板要求的 `7340606325656654345` 确实已被写进草稿**，
但草稿里**同时存在** `7504926415540817178`（指向 `Cache/effect/...`，即默认字体）。

**渲染结果仍未使用手写体**——说明还有一层未查明，可能是：
- 字体文件的命名/格式与剪映期望的不完全一致；
- 或渲染时字体加载路径与本机 GUI 不同；
- 或默认字体在样式链里优先级更高。

## 没做到的事（不夸大）

**我没有让手写体真正在成片里生效。** 字体文件补齐和字体 id 写入都已验证，
但最终画面仍是默认发光体。这一层需要继续排查。

## 建议的下一步

**最直接的验证**：请你在剪映 GUI 里打开这个草稿
（`com.lveditor.draft/guzhu-01`），看字体在 GUI 里显示是否正常：

- **如果 GUI 里正常** → 说明字体文件没问题，是 CLI 渲染路径的问题；
- **如果 GUI 里也不对** → 说明字体文件仍需按 GUI 的方式重新下载。

这样能一步确认问题在哪一层，不用继续盲试。
